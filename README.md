# Финансовая отчётность

Клиентская панель и редактирование финансовых отчётов. Основной вариант для Plesk — PHP 8.1+ с SQLite: установка Node.js, npm и MySQL не требуется. Вход и восстановление сделаны по подходу проекта `kkkola000/price_stock`: PHP-сессии, password_hash/password_verify, CSRF и одноразовый файл-разрешение для сброса пароля.

## Развёртывание в Plesk

1. Получите ветку `main` и разверните проект в `/httpdocs/seller`.
2. Включите PHP 8.1+ (предпочтительно PHP-FPM). В расширениях PHP должны быть `PDO` и `pdo_sqlite`.
3. Если домен был переведён на Node.js, отключите обработку домена через Node.js и включите PHP. Корень документов домена для указанных ниже адресов — `/httpdocs`.
4. Каталоги `/httpdocs/seller/data` и `/httpdocs/seller/storage` должны быть доступны для записи пользователю PHP. Права 777 не нужны.
5. В «Настройках Apache и nginx» отключите прямую раздачу статических файлов через nginx для этого размещения: правила `.htaccess` должны закрывать `seller/data`, `seller/storage`, `.git`, тесты и node_modules. Если домен работает только на nginx, администратор должен явно запретить HTTP-доступ к этим каталогам в конфигурации nginx. Проверьте, что `/seller/data/finance.sqlite` возвращает 403/404, а не файл.
6. Включите HTTPS.

Адреса:

- Админка: `/seller/public/index.html`.
- Клиент: `/seller/public/client.html`.
- Восстановление: `/seller/public/reset-password.php`.
- Проверка PHP API: `/seller/public/api.php?action=csrf` возвращает JSON с токеном сессии.

HTML обращается к `api.php` рядом с собой. Никаких правил переписывания для `/api/` не нужно. XLSX-библиотека включена в `public/vendor`, установка npm на хостинге не требуется.

### Вход

На **новой базе**: логин `admin`, пароль `Admin123456!`. При первом входе требуется заменить стандартный пароль (12–256 символов). В «Настройках доступа» задайте клиентский код (8–256 символов); до его установки клиентский вход закрыт. Для последующих изменений нужен текущий пароль.

Если ранее работала Node.js-версия и в базе уже есть доступы, PHP сохраняет логин и отчёты, но не сбрасывает пароль на стандартный. Хеш scrypt из Node.js не совместим с password_verify PHP: один раз восстановите пароль по инструкции ниже, затем установите клиентский код в админке. Запускайте только один выбранный backend для реальных данных, не переключайте PHP и Node.js попеременно: таблицы доступа у них отдельные.

### Восстановление без SSH

1. В файловом менеджере Plesk откройте `/httpdocs/seller/storage`.
2. Создайте пустой файл `reset.allow`.
3. Откройте `/seller/public/reset-password.php` (также ссылка «Забыли пароль?» на входе).
4. Укажите логин и новый пароль, подтвердите его.
5. После успешной смены файл-разрешение удаляется. Все прежние сеансы завершаются. Отчёты и клиентский код PHP сохраняются.

Без файла разрешения сброс недоступен. Для нового разрешения нужен доступ к файлам сайта. Секреты в URL не передаются.

## Отчёты

Доходы слева, расходы справа, все строки видны. Названия и суммы редактируются; записи добавляются и удаляются. Каждый год содержит отдельные месячные отчёты. Итоги рассчитываются автоматически. Суммы вводятся без минуса, до двух десятичных знаков; расходы отображаются с минусом. После изменения нажмите «Сохранить отчёт». Клиент видит сохранённые данные при загрузке периода.

Импорт XLSX/CSV: выберите файл, лист (XLSX), столбцы названия и суммы (A, B, AA), начальную строку и тип записей. Проверьте предпросмотр, добавьте строки и сохраните. Повторный импорт создаёт дубликаты. Максимум 5 МБ и 2000 записей на месяц. CSV: UTF-8, разделитель запятая или точка с запятой. XLSX использует сохранённые результаты формул, сами формулы не вычисляет.

Текущая версия — один администратор и один клиентский кабинет с общим набором отчётов.

## Хранение

SQLite: `data/finance.sqlite` (или `DATA_DIR/finance.sqlite`, если переменная задана). Для работающей базы используйте SQLite backup API; для копирования файлов остановите запись и сохраните весь каталог, включая WAL. Не удаляйте `data` при обновлении. PHP-сеансы действуют 8 часов; смена пароля отзывает прежние сеансы, смена кода — клиентские. Пароль и код хранятся только в виде хешей. Лимит попыток входа хранится в SQLite.

## Проверки

```sh
php -l public/bootstrap.php
php -l public/api.php
php -l public/reset-password.php
python3 test/php_integration.py
```

`PHP_BIN` позволяет указать CLI PHP Plesk, например `/opt/plesk/php/8.3/bin/php`. Интеграционная проверка использует временную копию `public` и отдельную базу, запускает PHP-сервер, проверяет CSRF, вход, смену пароля, отчёты, разделение месяцев, восстановление, отзыв сеансов и клиентские права.

## Дополнительный режим Node.js

Для разработки остаётся сервер Node.js 24+: `npm ci` и `npm start`. Админка `/admin`, клиент `/`, API `/api/`. Используются собственные сессии Node.js и таблица credentials. PHP-маршруты `.html` обслуживаются PHP, а не Node.js; для полного сценария Plesk используйте PHP-режим выше. Проверки Node.js: `npm test`. Переменные Node.js: `PORT`, `HOST`, `DATA_DIR`, `APP_ORIGIN`, `NODE_ENV=production` для HTTPS cookie. Старые `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `CLIENT_CODE` импортируются только в пустую базу.
