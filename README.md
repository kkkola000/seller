# Финансовая отчётность

Веб-приложение для размещения на хостинге с Plesk и поддержкой Node.js 24+. SQLite не требует отдельного сервера базы данных.

## Установка и запуск

```sh
npm ci
export ADMIN_LOGIN='admin'
# Установите собственные ADMIN_PASSWORD и CLIENT_CODE через настройки среды.
npm start
```

Обязательные переменные: `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `CLIENT_CODE`. Без них API сообщает об отсутствии конфигурации. Не используйте один код для разных независимых клиентов: текущая версия рассчитана на один клиентский кабинет с одним набором отчётов.

Дополнительные: `PORT` (3000), `HOST` (0.0.0.0), `DATA_DIR` (каталог `data` рядом с server.js), `APP_ORIGIN` (внешний HTTPS origin, например `https://finance.example.com`, для проверки запросов за reverse proxy), `NODE_ENV=production` (Secure cookie; необходим HTTPS).

`/` — клиентский вход по коду. `/admin` — вход администратора по логину и паролю. После входа администратор создаёт год и заполняет каждый месяц отдельно. Названия и суммы редактируются, строки добавляются и удаляются, итоги рассчитываются автоматически. Суммы вводятся без минуса, до двух знаков после запятой; расходы показываются с минусом. Изменения видны клиенту после сохранения и загрузки отчёта. Демо-данные не записываются.

Импорт XLSX/CSV: выберите файл, лист (для XLSX), столбцы названия и суммы (A, B, AA и т. д.), начальную строку и тип записей. Проверьте предпросмотр, добавьте строки и сохраните отчёт. Импорт добавляет записи, повторный импорт создаёт дубликаты. Максимум 5 МБ на файл и 2000 строк в месяце. CSV: UTF-8, разделитель запятая или точка с запятой; десятичную запятую при разделителе запятая заключайте в кавычки. XLSX: сохранённые значения формул; формулы не вычисляются приложением.

## Plesk

1. Загрузите репозиторий, включите Node.js 24+ для домена.
2. Application root — корень проекта; document root — `public`; startup file — `server.js`. Все маршруты, включая `/api`, должны обслуживаться Node.js.
3. Установите зависимости через `npm ci`.
4. В настройках переменных приложения задайте обязательные переменные, `NODE_ENV=production`, `APP_ORIGIN=https://ваш-домен` и постоянный `DATA_DIR`, доступный для записи пользователю приложения. Подключите HTTPS.
5. Перезапустите приложение и проверьте входы на `/` и `/admin`.

SQLite хранит данные в `DATA_DIR/finance.sqlite`. Каталог должен переживать обновления приложения и не быть доступен по HTTP. Для резервирования работающей базы используйте SQLite backup API или остановите приложение перед копированием всего каталога (включая WAL). Сессии действуют 8 часов и сбрасываются при перезапуске. Запускайте один процесс приложения: сессии и ограничение попыток входа находятся в памяти. Пароли и код берутся из окружения, в базу и клиентский JavaScript не записываются.

```sh
npm test
```

Проверки: вход, ограничения доступа, сохранение и чтение отчётов, независимость месяцев, валидация, удаление записей и выход.
