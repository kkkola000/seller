# Финансовая отчётность

Веб-приложение для размещения на хостинге с Plesk и поддержкой Node.js 24+. SQLite не требует отдельного сервера базы данных.

## Установка и запуск

```sh
npm ci
npm start
```

### Вход и настройки доступа

Для нового сайта переменные паролей и SETUP_KEY не нужны. Откройте `/admin`:

- Логин: `admin`
- Начальный пароль: `Admin123456!`

При первом входе обязательно замените пароль (12–256 символов) в форме «Настройки доступа». До замены сервер не разрешает доступ к отчётам. Там же задайте код клиента (8–256 символов); до установки кода клиентский вход закрыт. Затем пароль и код можно менять кнопкой «Настройки доступа» в админке, подтвердив текущий пароль. После смены пароля другие сессии администратора завершаются; после смены кода завершаются клиентские сессии.

Обновление не сбрасывает ранее созданные доступы. Для совместимости, при отсутствии записи в базе, полный набор `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `CLIENT_CODE` переносится из окружения в базу при запуске. В дальнейшем изменения выполняются в админке. Частично заданные переменные не используются.

В SQLite сохраняются логин и хеши пароля/кода: для каждого секрета используется отдельная случайная соль и scrypt. Сохраняйте каталог базы при обновлениях: он содержит и отчёты, и доступы. Стандартный пароль замените сразу после развёртывания.

Дополнительные: `PORT` (3000), `HOST` (0.0.0.0), `DATA_DIR` (каталог `data` рядом с server.js), `APP_ORIGIN` (внешний HTTPS origin, например `https://finance.example.com`, для проверки запросов за reverse proxy), `NODE_ENV=production` (Secure cookie; необходим HTTPS).

`/seller/public/index.html` — дополнительный адрес входа администратора. Он работает через тот же сервер Node.js; API остаётся на `/api/`. В Plesk запросы `/api/` должны попадать в Node.js, а не в статический файловый сервер. Открытие HTML через `file://` не поддерживается.

`/` — клиентский вход по коду. `/admin` — вход администратора по логину и паролю. После входа администратор создаёт год и заполняет каждый месяц отдельно. Названия и суммы редактируются, строки добавляются и удаляются, итоги рассчитываются автоматически. Суммы вводятся без минуса, до двух знаков после запятой; расходы показываются с минусом. Изменения видны клиенту после сохранения и загрузки отчёта. Демо-данные не записываются.

Импорт XLSX/CSV: выберите файл, лист (для XLSX), столбцы названия и суммы (A, B, AA и т. д.), начальную строку и тип записей. Проверьте предпросмотр, добавьте строки и сохраните отчёт. Импорт добавляет записи, повторный импорт создаёт дубликаты. Максимум 5 МБ на файл и 2000 строк в месяце. CSV: UTF-8, разделитель запятая или точка с запятой; десятичную запятую при разделителе запятая заключайте в кавычки. XLSX: сохранённые значения формул; формулы не вычисляются приложением.

## Plesk

1. Загрузите репозиторий, включите Node.js 24+ для домена.
2. Application root — корень проекта; document root — `public`; startup file — `server.js`. Все маршруты, включая `/api`, должны обслуживаться Node.js.
3. Установите зависимости через `npm ci`.
4. В настройках переменных приложения задайте `NODE_ENV=production`, `APP_ORIGIN=https://ваш-домен` и постоянный `DATA_DIR`, доступный для записи пользователю приложения. Подключите HTTPS.
5. Перезапустите приложение и проверьте входы на `/` и `/admin`.

SQLite хранит данные в `DATA_DIR/finance.sqlite`. Каталог должен переживать обновления приложения и не быть доступен по HTTP. Для резервирования работающей базы используйте SQLite backup API или остановите приложение перед копированием всего каталога (включая WAL). Сессии действуют 8 часов и сбрасываются при перезапуске. Запускайте один процесс приложения: сессии и ограничение попыток входа находятся в памяти. Открытые пароли и коды не передаются в клиентский JavaScript. В базе хранятся только хеши.

```sh
npm test
```

Проверки: вход, ограничения доступа, сохранение и чтение отчётов, независимость месяцев, валидация, удаление записей и выход, замена стандартного пароля, смена кода и отзыв сеансов.
